# Agent Instructions

This project uses `tracking.db` and `TRACKING_GUIDE.md` as living technical
memory.

Before meaningful work:

1. Read `TRACKING_GUIDE.md`.
2. Query open tracker items from `tracking.db`.
3. Reuse an existing item when related.
4. Create a new tracker item when the work is meaningful and no related item
   exists.
5. Update tracker events for decisions, implementation, risks, scope changes,
   and verification.

Do not mark work `verified` unless `finished_state` and `verification` are both
filled.

Treat the tracker as technical documentation, not just a todo list.
